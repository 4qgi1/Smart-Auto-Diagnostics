# 🔧 Smart Auto Diagnostics — نظام التشخيص الميكانيكي الذكي

برنامج جافا يعمل كـ«مهندس ميكانيكي آلي»: يسأل صاحب السيارة أسئلة متسلسلة عن العَرَض الذي يواجهه، ثم يطبع **تقريرًا** يحدد العطل المحتمل وحله — بدل التخمين أو دفع مبالغ على فحص عشوائي للقطع.

المركبة المدعومة حاليًا: **شفروليه تاهو بمحرك V8** (5.3 لتر).

---

## 💡 الفكرة

1. **الاستقبال:** يسأل البرنامج: «وش العرض اللي تواجهه في سيارتك الآن؟» ويعرض الأعراض الرئيسية.
2. **التحقيق الذكي:** حسب اختيارك يطرح أسئلة أدق، وكل سؤال يُبنى على إجابة السؤال الذي قبله (شجرة قرار).
3. **النتيجة:** تقرير فيه مسار الأسئلة، العطل المحتمل، درجة اليقين، درجة الخطورة، والحل المقترح.

### الأعراض المدعومة

| العَرَض | عدد الأسئلة | عدد الأعطال الممكنة | أمثلة على النتائج |
|---|---|---|---|
| تفتفة في المحرك | 10 | 13 | رافعة AFM منهارة، كويل تالف، شمعات منتهية، تسرب فراغ |
| طقطقة مع انخفاض ضغط الزيت | 5 | 8 | تسرب زيت، حساس ضغط، Rod Knock، مضخة زيت |
| ارتفاع حرارة المحرك | 5 | 7 | ثرموستات عالق، مروحة، وسادة رأس، تسرب تبريد |

رسم كل شجرة بالتفصيل: [`docs/decision-trees.md`](docs/decision-trees.md) (يُعرض تلقائيًا على GitHub).

## ▶️ التشغيل

**المتطلبات:** Java 11 أو أحدث.

```bash
./run.sh          # تشغيل البرنامج
./run.sh test     # تشغيل الاختبارات
./run.sh docs     # إعادة توليد مخططات الشجرة
```

أو يدويًا:

```bash
# macOS / Linux
mkdir -p out && javac -encoding UTF-8 -d out $(find src test -name "*.java")
java -cp out com.smartauto.Main
```

```bat
:: Windows (cmd)
chcp 65001
mkdir out
dir /s /b src\*.java test\*.java > sources.txt
javac -encoding UTF-8 -d out @sources.txt
java -cp out com.smartauto.Main
```

> **ملاحظات للعرض العربي:** البرنامج يطبع بترميز UTF-8. في IntelliJ يظهر العربي سليمًا في الكونسول. في الطرفية القديمة في Windows شغّل `chcp 65001` أولًا.

### التحكم أثناء الأسئلة

- اكتب **رقم الخيار** (يقبل الأرقام العربية ١٢٣ أيضًا).
- اكتب **0** للرجوع للسؤال السابق.
- الإدخال الخاطئ لا يوقف البرنامج؛ يعيد السؤال.
- بعد النتيجة تستطيع **حفظ التقرير** في مجلد `reports/`.

## 🧠 مفاهيم البرمجة الكائنية المستخدمة

| المفهوم | أين يظهر في المشروع |
|---|---|
| **Abstraction** | `DecisionNode` كلاس مجرّد يمثل «أي عقدة» دون تفاصيل |
| **Inheritance** | `QuestionNode` و `ResultNode` يرثان من `DecisionNode` |
| **Polymorphism** | `DiagnosticSession` يتعامل مع أي عقدة عبر `isLeaf()` دون معرفة نوعها |
| **Encapsulation** | حقول `private`، قوائم غير قابلة للتعديل، و`Diagnosis` كائن ثابت (immutable) |
| **Interface** | `VehicleKnowledgeBase` — أي سيارة جديدة تنفّذها دون تعديل بقية النظام |
| **Builder Pattern** | `Diagnosis.builder(...)` يجعل بناء التشخيص مقروءًا ويمنع النتائج الناقصة |
| **Enum** | `Severity` و `Confidence` بدل نصوص حرّة |
| **Separation of Concerns** | الواجهة (`ui`) لا تعرف المنطق، والمنطق (`engine`) لا يعرف الطباعة |

**لماذا هذا التصميم يهم؟** لأن `DiagnosticSession` لا يطبع ولا يقرأ من الكيبورد؛ لذلك اختبرناه آليًا بدون أي واجهة، ويمكن لاحقًا وضع واجهة رسومية أو تطبيق جوال فوق نفس المنطق.

## ➕ كيف تضيف عَرَضًا أو سيارة جديدة

### عَرَض جديد لنفس السيارة

1. أنشئ كلاسًا مثل `MisfireTree` في `knowledge/tahoe/` بنفس الأسلوب (من الأوراق إلى الجذر):

```java
ResultNode battery = leaf(Diagnosis.builder("BATTERY_WEAK", "بطارية ضعيفة")
        .explanation("المارش يدور ببطء لأن البطارية لا تعطي تيارًا كافيًا.")
        .solution("افحص جهد البطارية وبدّلها إن كانت ضعيفة.")
        .severity(Severity.LOW)
        .confidence(Confidence.MEDIUM));

QuestionNode root = ask("S_ROOT", "هل المارش يدور ببطء؟", null)
        .choice("نعم", battery)
        .choice("لا", otherNode);

return new Symptom("NO_START", "السيارة لا تشتغل", "المحرك لا يدور عند التشغيل.", root);
```

2. أضف `NoStartTree.build()` في قائمة `TahoeV8KnowledgeBase`.
3. شغّل `./run.sh test` — المدقّق يخبرك فورًا إن كانت الشجرة فيها خطأ (سؤال بخيار واحد، حلقة، رمز مكرر...).

### سيارة جديدة

1. أنشئ كلاسًا ينفّذ `VehicleKnowledgeBase` (اسم السيارة + قائمة الأعراض).
2. سجّله في `KnowledgeBaseRegistry.loadAll()`.
3. الواجهة ستعرض قائمة اختيار السيارة تلقائيًا عندما يصبح عددها أكثر من واحدة.

## ⚠️ حدود المشروع

- المحتوى الميكانيكي مبني على **أعطال شائعة ومعروفة** في محركات V8 من فئة 5.3 لتر (خصوصًا نظام AFM)، وهو **مرجع تعليمي** وليس بديلًا عن دليل الخدمة الرسمي أو فحص فني.
- بعض التفاصيل تختلف بحسب **سنة الصنع والفئة** (نوع الزيت، نوع مروحة التبريد، فترات تبديل الشمعات)، ولذلك تُحال في النتائج إلى دليل المالك.
- التشخيص **مبدئي**: التقرير يوضح «درجة اليقين» لكل نتيجة ويطلب التأكد في ورشة قبل شراء القطع.

## 🚀 أفكار للتطوير

- واجهة رسومية (JavaFX) أو تطبيق ويب فوق نفس المنطق.
- قراءة أكواد OBD2 مباشرة بدل سؤال المستخدم عنها.
- تحميل الأشجار من ملفات JSON بدل كتابتها في الكود.
- إضافة سيارات وأعراض جديدة (بطارية، فرامل، ناقل الحركة).
